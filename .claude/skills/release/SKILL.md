Готовим релиз. Действуй строго по порядку и остановись при первой проблеме.

1. Все изменения в ветке, ветка актуальна относительно `main`, `npm test` зелёный.
2. `/review` по изменениям с прошлого релиза (`git diff <прошлый тег>..HEAD`). Блокирующие находки — стоп.
3. Проверь: миграции только расширяющие (если сезон идёт), флаги новых механик в конфиге по умолчанию выключены, `docs/RUNBOOK.md` и `docs/GLOSSARY.md` актуальны. Замер памяти `npm run test:memory` на образе релиза: пик не выше бюджета 400 МБ (CLAUDE.md «Эксплуатация»), иначе стоп.
4. Собери заметки к релизу из коммитов с прошлого тега — они пойдут на страницу «Что нового». Покажи мне итог шагов 1–4 и дождись подтверждения.
5. Создай PR в `main` (`gh pr create`), дождись зелёного CI, включая E2E и проверку миграций (`gh pr checks --watch`). После моего подтверждения — слияние.
6. Дождись автоматической выкладки на тестовую копию и её дымовых тестов (`gh run watch`). Покажи результат и ссылку на тестовую копию, дождись подтверждения.
7. Запусти выкладку на боевой сайт (`gh workflow run deploy-prod.yml` с версией, прошедшей тестовую копию) только после моего явного «выкладывай». Следи за прогоном до конца.
8. Проверь `/health`, главную и страницу «Что нового» на боевом сайте. Обнови `docs/PROGRESS.md`.

Если GitHub Actions недоступен, запасной путь — `npm run deploy:prod` по `docs/RUNBOOK.md`, тоже только после моего подтверждения.
