# Пакет предметов из старой таблицы

Предметы из листа «Предметы» таблицы «Игры крутить» (514 записей), переведённые в формат `docs/CONTENT.md`. Это сырьё для этапа 4, а не готовый баланс.

## Файлы

| Файл | Что внутри |
| --- | --- |
| `items.json` | 112 предметов с автоматическим эффектом и 2 эффекта (`bubble-effect`, `bomb`) |
| `items.manual.json` | 269 предметов только с текстом: `manual: true`, по умолчанию `enabled: false` |
| `wheels.json` | 8 лутбоксов, на которые ссылаются предметы-лутбоксы |
| `TRIAGE.csv` | все 514 записей: статус «авто», «вручную» или «исключён» и причина |

## Статусы

- **Авто** — эффект собран из базовых действий и работает без ведущего.
- **Вручную** — предмет допустим, но его текст не собирается из базовых действий без новых механик. Такой предмет — текстовая карточка, при использовании уходит в ручное разрешение. По умолчанию выключен: Даниил включает выборочно.
- **Исключён** (133) — противоречит правилам сайта:
    - зависит от онлайна (59);
    - хлам и крафт (16);
    - золотые версии и бесконечные цепочки бросков монетки (21);
    - нужны действия вне сайта или ведущий (12);
    - механики колёс из старых правил (6);
    - время суток, слова в названиях, место в лидерборде (14);
    - дают или забирают очки, а у нас очки — это место в рейтинге (5).

  Даниил может вернуть любой предмет, поменяв статус в `TRIAGE.csv`.

## Что нужно учесть при импорте

1. **Золото = монетки.** В описаниях осталось старое слово «золото» и опечатки оригинала. При импорте перепиши тексты для игроков по `docs/GLOSSARY.md`, смысл не меняй.
2. **Редкость** взята из приставки названия. «Редкий» и «Эпический» — это `epic`, «Легендарный» и «Мифический» — `legendary`. Без приставки: цена от 60 — `legendary`, от 30 — `epic`, иначе `common`.
3. **Цены** перенесены как есть. Цена −1 в оригинале означает «не продаётся», здесь это `price: null`: такой предмет достаётся только из лутбоксов, клеток и ивентов. Числа временные, баланс — после симуляции.
4. **Теги** (`edible`, `weapon`, `potion`, `rat`, `gremlin`, `pig`) нужны для фильтров вроде «не может украсть крысиные» и для лутбоксов. Поле `tags` — дополнение к формату CONTENT.md.
5. **Поле `requires`** у каждого предмета перечисляет расширения формата сверх базового CONTENT.md. 64 предмета не требуют ничего. Импортируй предмет, только когда все его расширения реализованы; остальные оставь в очереди.
6. **Флаги** `unstealable` и `undestroyable` взяты из текста («Невозможно украсть», «Нельзя уничтожить»). `useCondition` — условие использования, например «только если у тебя 0 монеток».

## Расширения формата

Это параметры существующих базовых действий, а не новые действия. Их лимит из CLAUDE.md не нарушается.

| Расширение | Предметов | Смысл |
| --- | --- | --- |
| `reflect` | 18 | урон монетками уходит стреляющему вдвойне, если у цели монеток не больше порога из конфига (по умолчанию −30; идея из RGG-LAND) |
| `modifyDice.countWithSides` | 8 | дополнительный кубик заданного типа: `stage: count` с полем `sides` |
| `takeObject.countDynamic` | 5 | `count: "all"` или `count: "$roll"` |
| `move.direction` | 5 | направление из выбора (`$choice`: «вперёд» или «назад») или `away` — от стреляющего |
| `takeObject.give` | 4 | отдать свой объект другому игроку (свиньи); это передача через предмет, а не прямой перевод |
| `counters` | 5 | эффекты со счётчиком: сброс, изменение, уничтожение по признаку `hasCounter` |
| `selector:withinCells` | 4 | все игроки в пределах N клеток, с флагом `includeSameCell` |
| `selector:nearestBehind` | 1 | ближайший игрок позади; при равенстве — все |
| `modifyDice.setOne`, `multiply`, `replaceValue`, `fixAverage`, `bonusPerEven`, `singleDie`, `rerollFilter` | по 1–2 | редкие варианты этапов конвейера броска |
| `outcomes.choice` | 1 | ветвление по выбору игрока, а не по броску |
| `roll.as` | 1 | именованный результат броска (`$back`, `$fwd`), когда бросков в эффекте несколько |
| `useCondition` | 1 | условие, при котором предмет можно использовать |
| `intercept.badEvent` | 1 | перехват не только враждебного эффекта, но и плохого ивента (Бабл) |

Эффект `bomb` использует `counter` и `onCounterZero`: счётчик 3, минус один за каждое прохождение или дроп, на нуле — бросок d6 и ход назад.

## Порядок работы на этапе 4

1. Реализуй базовый формат CONTENT.md и импортируй 64 предмета без расширений.
2. Расширения добавляй по одному, начиная с самых частых: `reflect`, `countWithSides`, `countDynamic`, `move.direction`. Каждое — отдельная задача с тестами, после неё импортируй предметы, которые стали доступны.
3. Для каждого импортированного предмета — сценарный тест: описание для игрока совпадает с поведением.
4. Спорные трактовки не решай молча: записывай в `docs/DECISIONS.md` с пометкой «нужно решение».
5. Ручные предметы загрузи выключенными, чтобы Даниил мог включать их из админки.
