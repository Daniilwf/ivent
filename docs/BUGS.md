### FL-1. Тест зерна случайности в инструментах тестирования падал в CI: заголовок страницы забирал фокус посреди ввода

- **Найдено:** CI веток `feat/stage12-ui-tails` и `feat/stage2-close-graph` (2026-11-10), `TestToolsSection.test.tsx` «seed the randomness with a whole number only…»: «Unable to find an element with the text: Зерно — целое число, например 42.»; на `main` и локально зелёный.
- **Шаги:** в одном файле тестов сначала тест, который переходит по ссылке (`navigate`, «send the admin to the season»), потом тест, который открывает раздел и сразу печатает в поле.
- **Ожидалось:** каждый тест — новый визит сайта: первая страница фокус не трогает, напечатанное «4.2» остаётся в поле, форма отвечает «Зерно — целое число».
- **Получилось:** флаг роутера «страница открыта ссылкой» (`navigated`, модульное состояние) оставался от прошлого теста, и `usePageHeading` через кадр переносил фокус на заголовок раздела. В jsdom кадр — независимый таймер, и на медленной машине он приходил, когда тест уже напечатал «4»: «.2» уходило в заголовок, форма отправляла зерно 4 без ошибки. Воспроизведено детерминированно: кадр задержан до середины ввода — тот же текст ошибки, отправлено `{ seed: 4 }`. В браузере не воспроизводится: кадр приходит до отрисовки, поле раньше него не увидеть, — ошибка изоляции тестов, а не сайта.
- **Важность:** низкая — ошибка тестов, красный CI на чужих ветках.
- **Тест:** `web/src/app/router.test.tsx` («a page opened by a link takes the focus to its heading» и следом «the first page of a test is the first of a visit…» — падал до исправления).
- **Исправление:** `forgetNavigation()` в роутере (только для тестов), вызывается перед каждым тестом в `web/src/test/setup.ts` рядом с `forgetSiteEnvironment()`.

### FL-2. Тесты формы игры и редактора карты ждали ответа после задержки формы обычную секунду

- **Найдено:** под нагрузкой машины (2026-11-10): `PoolScreen.test.tsx` «refuses the same title before sending», `MapSection.test.tsx`.
- **Шаги:** напечатать название в форме игры (или изменить карту) и ждать предупреждения о похожих играх (проверки карты) стандартным `findBy…`.
- **Ожидалось:** тест ждёт ответ столько, сколько он реально идёт: задержка формы плюс обычное время на ответ и отрисовку.
- **Получилось:** форма спрашивает сервер только через 400 мс после последней правки (`similarDelayMs`, `checkDelayMs`), и из секунды Testing Library на ответ и отрисовку оставалось 600 мс — на загруженной машине не хватало.
- **Важность:** низкая — ошибка тестов.
- **Тест:** те же тесты; ожидания сквозь задержку — `pastTheDelay(delay)` из `web/src/test/waits.ts` (задержка формы + обычная секунда), остальные ожидания не тронуты.
- **Исправление:** `findBy…` после правки, которые ждут ответ сквозь задержку формы, ждут её явно; `checkDelayMs` экспортирован из `MapSection.tsx`.

### I1-1. Главная на мобильной сети ждала три запроса подряд, прежде чем спросить сезон

- **Найдено:** E2E-сценарий 13 «Скорость главной на демо-сезоне» (I1): Slow 4G (150 мс, 1,6 Мбит/с), первый визит, ответы сжаты как за Caddy.
- **Шаги:** войти игроком демо-сезона, открыть главную с пустым кэшем на медленной сети.
- **Ожидалось:** основное содержимое (название сезона, карточка хода, карта с фишками) быстрее 2,5 с (`docs/DESIGN.md` «Производительность») с запасом.
- **Получилось:** 2,44–2,47 с по часам страницы (без сжатия — 5,5 с): после скрипта страница по очереди спрашивала токен CSRF, затем `/api/auth/me`, затем `/api/seasons/current` и только потом сезон — три круга по 150–180 мс впустую.
- **Важность:** средняя — бюджет на грани, любая добавка к главной его ломает.
- **Тест:** `web/src/App.test.tsx` «asks who is signed in, the current season and the antiforgery token at once»; `e2e/tests/late/s13-speed.spec.ts`.
- **Исправление:** `App` спрашивает токен, пользователя и текущий сезон одновременно; сезон берётся из уже заданного вопроса. Стало 2,12–2,14 с. Дальше главную можно ускорить, вынеся админку и прочие страницы в отдельные чанки (главный скрипт 246 КБ в gzip), — не сделано, запаса пока хватает. **Исправлено.**

### C13-1. Откат команды стирал более позднюю команду, которая ничего не изменила

- **Найдено:** длинный прогон случайных партий (C13, `npm run test:invariants:long`), свойство `UndoTests.An_accepted_undo_equals_the_log_without_the_command`; минимальный сценарий напечатан кодом билдера.
- **Шаги:** игрок завершает прохождение; отправляет пруф; отправляет тот же пруф ещё раз (те же ссылки, в ту же минуту — состояние не меняется); админ откатывает первую отправку.
- **Ожидалось:** откат отказывает — вторая отправка зависит от того же прохождения (D-20, D-104), её событие стоит в логе.
- **Получилось:** откат принят, пруф исчез целиком вместе со второй отправкой; сезон перестал совпадать с логом без отменённой команды (инвариант 13), а поздняя команда игрока потерялась. Причина: зависимые команды искались только по изменениям состояния, а у повторной отправки изменений нет.
- **Важность:** средняя — редкий путь (повтор без изменений), но тихо теряет действие игрока и ломает инвариант отката.
- **Тест:** `Undo/UndoTests.A_later_command_that_repeated_the_change_blocks_the_undo`.
- **Исправление:** ключи команды для отката включают игрока, прохождение и эффект, о которых говорят сами события (`GameIds.Own`), даже если состояние не изменилось. **Исправлено.**
