### K3-1. Проверка бэкапа отклоняет базу, созданную на Windows

- **Найдено:** закрытие этапов 1–2 (K3, 2026-11-14): демо-сезон, засеянный на Windows (`seed-demo`), положен в том сайта на локальном Docker; `dc run --rm backup` и `backup-verify`.

### INV-2. Заморозка при одобрении с понижением сложности шла раньше самого одобрения

- **Найдено:** длинный прогон инвариантов (2026-11-13), `PlayerAdminInvariantTests.Invariants_hold_in_the_combined_game_with_rerolls_and_a_choice_of_games`, зерно 20, скрипт `[34, 1, 13, 160, 165, 73, 28, 192, 38, 74, 48, 178, 240]`; на `main` (128ca11), в Debug и Release.
- **Шаги:** Петя финиширует первым на сложной (d6: 3 + 1, запаса нет), Маша финиширует второй, её прохождение одобрено (она не первая — не заморожена). Админ одобряет Петино прохождение, понизив сложность до нормальной (`ApproveProof` со сложностью): кубы d4 2 + 1 — на шаг меньше, Петин финиш снимается, первой становится Маша, все её прохождения до финиша одобрены.
- **Ожидалось:** Маша заморожена в той же команде, и, как у любой заморозки одобрением (Q-3, D-99), `PlayerFrozen` — последнее событие, после `ProofApproved`.
- **Получилось:** `PlayerFrozen(Маша)` писался внутри смены сложности (снятие финиша → пересчёт мест `Finishes.Settle` → заморозка), до `ProofApproved`; проверка Q-3 «заморозка — последнее событие» падала. Итоговое состояние было верным, неверен порядок событий в логе.
- **Важность:** низкая — состояние и места верны; но порядок лога — публичный контракт (лента, повтор), а красный длинный прогон маскировал бы настоящие нарушения.
- **Тест:** `src/GameEvent.Engine.Tests/Finish/LoweredApprovalFreezeTests.Approval_at_a_lower_difficulty_revoking_the_first_freezes_the_next_after_the_approval` (падал до исправления); `src/GameEvent.Engine.Tests/Invariants/PlayerAdminInvariantTests.Combined.cs` («An_approval_at_a_lower_difficulty_that_revokes_the_first_freezes_the_next_after_the_approval» — найденная партия как фиксированный скрипт).
- **Исправление:** `ApproveProof` берёт события смены сложности без `PlayerFrozen` и решает заморозку один раз, после одобрения (`Finishes.FreezeIfDue` по состоянию после всей команды). Между выброшенной и итоговой заморозкой первый и одобрения его прохождений не меняются (ивент сложности владельца не финиширует и по первому не бьёт — цели отсекаются по `FinishLine.First`), поэтому итог тот же игрок и ровно одна заморозка. Отдельные правки (`ChangeRunDifficulty`, `CorrectRunHours`) и реджект со штрафом не менялись: правило Q-3 «заморозка — последнее событие» проверяется у одобрения, у правок заморозка вместе с пересчётом мест, где её и решает отзыв финиша.

- **Шаги:** сценарий 1 на десктопе: админ уже на странице очереди, Вася завершает прохождение (карточка появляется без пруфа), потом присылает пруф.
- **Ожидалось:** тест ждёт ссылку пруфа столько же, сколько любое живое обновление админки (`adminRefresh`, 15 с, D-231).
- **Получилось:** карточка с «Вася» уже была (от завершения), ссылка ждалась 5 с по умолчанию и не успела — «Пруф не прислан».
- **Важность:** низкая — ошибка теста, не сайта.
- **Тест:** `e2e/tests/s01-full-cycle.spec.ts`.
- **Исправление:** ожидание ссылки — с `adminRefresh`.

### I1-1. Главная на мобильной сети ждала три запроса подряд, прежде чем спросить сезон

- **Найдено:** E2E-сценарий 13 «Скорость главной на демо-сезоне» (I1): Slow 4G (150 мс, 1,6 Мбит/с), первый визит, ответы сжаты как за Caddy.
- **Шаги:** войти игроком демо-сезона, открыть главную с пустым кэшем на медленной сети.
- **Ожидалось:** основное содержимое (название сезона, карточка хода, карта с фишками) быстрее 2,5 с (`docs/DESIGN.md` «Производительность») с запасом.
- **Получилось:** 2,44–2,47 с по часам страницы (без сжатия — 5,5 с): после скрипта страница по очереди спрашивала токен CSRF, затем `/api/auth/me`, затем `/api/seasons/current` и только потом сезон — три круга по 150–180 мс впустую.
- **Важность:** средняя — бюджет на грани, любая добавка к главной его ломает.
- **Тест:** `web/src/App.test.tsx` «asks who is signed in, the current season and the antiforgery token at once»; `e2e/tests/late/s13-speed.spec.ts`.
- **Исправление:** `App` спрашивает токен, пользователя и текущий сезон одновременно; сезон берётся из уже заданного вопроса. Стало 2,12–2,14 с. Дальше главную можно ускорить, вынеся админку и прочие страницы в отдельные чанки (главный скрипт 246 КБ в gzip), — не сделано, запаса пока хватает. **Исправлено.**

### C13-1. Откат команды стирал более позднюю команду, которая ничего не изменила

- **Найдено:** длинный прогон случайных партий (C13, `npm run test:invariants:long`), свойство `UndoTests.An_accepted_undo_equals_the_log_without_the_command`; минимальный сценарий напечатан кодом билдера.
- **Шаги:** игрок завершает прохождение; отправляет пруф; отправляет тот же пруф ещё раз (те же ссылки, в ту же минуту — состояние не меняется); админ откатывает первую отправку.
- **Ожидалось:** откат отказывает — вторая отправка зависит от того же прохождения (D-20, D-104), её событие стоит в логе.
- **Получилось:** откат принят, пруф исчез целиком вместе со второй отправкой; сезон перестал совпадать с логом без отменённой команды (инвариант 13), а поздняя команда игрока потерялась. Причина: зависимые команды искались только по изменениям состояния, а у повторной отправки изменений нет.
- **Важность:** средняя — редкий путь (повтор без изменений), но тихо теряет действие игрока и ломает инвариант отката.
- **Тест:** `Undo/UndoTests.A_later_command_that_repeated_the_change_blocks_the_undo`.
- **Исправление:** ключи команды для отката включают игрока, прохождение и эффект, о которых говорят сами события (`GameIds.Own`), даже если состояние не изменилось. **Исправлено.**

### S4-2. Предмет, чей эффект удалён из пакета, тратился впустую

- **Найдено:** исследовательское тестирование этапа 4 (4.13), админ и игрок.
- **Шаги:** выдать Даше «Щит»; опубликовать пакет без `shield` и `shield-effect`; Даша жмёт «Использовать».
- **Ожидалось:** окно удаления обещает: «У игроков, которые его держат, он продолжит работать» — щит даёт свой эффект.
- **Получилось:** план предмета разрешал применение, команда принималась, но в логе только `object-removed` и `item-used`: эффекта нет, эпический предмет потерян. Обработчик `giveObject` молча пропускал удалённое определение.
- **Важность:** средняя — тихая потеря предмета игрока после обычной правки контента.
- **Тест:** `Economy/ContentPackTests.A_held_item_still_gives_its_effect_after_both_are_deleted`.
- **Исправление:** `giveObject` эффекта берёт определение и удалённым (D-780); админ удалённое по-прежнему не выдаёт, магазин не продаёт. **Исправлено.**

### S4-3. Вторая вкладка редактора контента молча теряла правку, когда другая сохраняла

- **Найдено:** исследовательское тестирование этапа 4 (4.13), админ в двух вкладках.
- **Шаги:** открыть «Банан» в вкладках A и B; в B поменять цену, не сохраняя; в A сохранить.
- **Ожидалось:** D-491: два админа не затирают правки друг друга молча — правка B остаётся, сохранение отказывает словами.

- **Важность:** низкая — два админа одновременно редки, но правка теряется без следа.
- **Тест:** `web/src/admin/content/ContentSection.test.tsx` «keeps an unsaved edit when another admin publishes meanwhile, and says so (S4-3)», «takes a newer version at once when nothing is open».

### S4-4. Таймер лотов магазина шёл по часам устройства
