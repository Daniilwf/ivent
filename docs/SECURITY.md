# Безопасность сайта

Итоги аудитов безопасности и что перепроверять перед каждым выпуском (`/release`). Решения — в `docs/DECISIONS.md`, находки — в `docs/BUGS.md` (префикс `SEC-`), тесты — в `docs/TEST_MATRIX.md`.

## Аудит 2026-11-11 (ветка `fix/security-audit-2026-11`, D-460…D-465)

Проверялся весь код, а не изменения. Каждая находка сначала воспроизведена падающим тестом, потом исправлена.

### Находки

| № | Важность | Что | Исправление |
| --- | --- | --- | --- |
| SEC-2 | средняя | Подбор пароля с трёх адресов (или трёх /64 одного хоста IPv6) держал 429 и для владельца с правильным паролем: потолок по логину запирал всех | Кука устройства: браузер, уже входивший в этот логин, потолок не держит, лимит своей пары держит (D-460) |
| SEC-4 | низкая | Кука устройства (первая версия SEC-2) хранила только логин: не истекала на сервере и переживала смену пароля — вошедший однажды сохранял обход потолка и после сброса | В куке id аккаунта, штамп безопасности и срок; после смены пароля, удаления и через год кука чужая (D-465) |
| SEC-3 | низкая | Каждый набранный при входе логин оставался в памяти навсегда | Чистка истёкших попыток раз в минуту (D-463) |
| SEC-1 | низкая | На странице не было CSP, кроме `frame-ancestors` (обещана в D-72) | Полная CSP на всех ответах, E2E без нарушений политики (D-462) |

## Перепроверять перед каждым выпуском

- `dotnet list GameEvent.slnx package --vulnerable --include-transitive` и `npm audit --omit=dev` в корне, `web/`, `e2e/` — пусто.
- `EndpointAuthorizationTests` зелёный; новый анонимный эндпоинт — только осознанно, со строкой в его списке и решением в `DECISIONS.md`.
- E2E `s14-csp` зелёный: новая библиотека фронтенда, которая грузит что-то со стороны или вставляет скрипт, ломает его, а не сайт.
- Дымовые тесты против тестовой копии и боевого сайта: заголовки, CSP, закрытые двери (`npm run test:smoke -- <адрес>`).
- На боевом сайте `/api/test` и `/openapi/v1.json` отвечают 404.

## Сессии на сервере (ветка `feat/sessions`, D-466…D-469, решение D-464 (1))

Каждый вход — строка таблицы `Session`; кука несёт её id, каждый запрос проверяет, что сессия жива. Выход отзывает эту сессию: скопированная до выхода кука получает 401 (`SessionTests.Sign_out_ends_the_session_and_a_copy_of_the_cookie_made_before_gets_401`). Самопроверка как ревьюер безопасности:

| Что | Как проверено | Итог |
| --- | --- | --- |
| Фиксация сессии | id сессии делает сервер (128 случайных бит) при каждом входе, кука выдаётся заново; подброшенная до входа кука не называет новую сессию; повторный вход в том же браузере завершает его прежнюю сессию | SES-1 исправлено |
| CSRF | Новые `POST` — в группе `/api` с фильтром антифорджери: кука без токена страницы ничего не завершает (`Ending_sessions_needs_a_command_id_the_antiforgery_token_and_a_sign_in`), `SameSite=Strict` | ✅ |
| Перебор чужих сессий | Чужая и несуществующая сессия — один и тот же 404 с одинаковым телом, путь кода одинаковый (выборка своих живых сессий, потом фильтр по id): по ответу и времени не отличить; список отдаёт только свои; «Выйти отовсюду» — только админ (403 игроку и зрителю, 401 анониму); id сессии подделать нельзя — кука зашифрована и подписана | ✅ |
| Время ответа | Проверка сессии — поиск по первичному ключу без сравнения секретов в коде; сравнение метки — как до сессий (метка не угадывается: 128 бит) | ✅ |
| Нагрузка | Последний заход пишется не чаще раза в 5 минут и одной командой на сессию за раз; строки создаёт только успешный вход (лимиты входа D-67, D-460) | число живых сессий одного аккаунта не ограничено — SES-2, отложено |
| Хаб | Отозванная сессия закрывает свои соединения сразу, переподключение получает 401 | соединение сессии, истёкшей по времени без единого запроса за 30 дней, живёт до переподключения — SES-3, отложено |
| Данные | Строка браузера и адрес — только в таблице `Session` (не в логе, не в ответах API, кроме строки браузера владельцу); строки завершённых сессий удаляет планировщик | ✅ |
| Старые куки | Без сессии — выход, вход заново один раз (D-467, `A_cookie_from_before_sessions_is_signed_out`) | ✅ |
