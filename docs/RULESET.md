# Конфиг правил сезона

Все игровые числа и флаги живут в конфиге сезона. Значения по умолчанию — `docs/ruleset.default.json`. Числа в нём временные, окончательные выставляются после симуляции.

## Правила работы с конфигом

- Конфиг описывается C#-типами в движке. JSON-схема генерируется из этих типов, тест проверяет, что `ruleset.default.json` проходит схему.
- Каждое число, которое использует движок, берётся из конфига. Балансных констант в коде нет.
- Всё, что касается прохождения, фиксируется в снапшоте при ролле. Остальное берётся из текущей версии конфига на момент действия.
- Каждое изменение конфига — новая версия с датой и автором. Игроки видят историю на странице правил.
- Админ правит конфиг как JSON с проверкой по схеме. Невалидный конфиг не сохраняется.
- Новые поля добавляются со значением по умолчанию, чтобы старые версии конфига продолжали читаться.

## Поля

### `version`

Версия формата документа (сейчас 1). Это не номер версии правил сезона: его ведёт сайт, 1 при создании сезона и +1 при каждой правке. Документ другого формата не принимается.

### `features` — флаги функций

| Поле | Что включает |
| --- | --- |
| `mapMode` | `linear` — цепочка клеток из `map.linearLength`, `graph` — карта-граф: сезон создаётся с картой, новые версии публикует админ (D-300). Сменить можно только `linear → graph` (D-301) |
| `items`, `shop`, `bets` | предметы и эффекты, магазин, ставки (этап 4, D-415). Магазин продаёт предметы: `shop` без `items` не принимается |
| `events` | ивенты и колоды (этап 5, D-500…D-502): клетка ивента и `drawEvent` тянут из колоды и разыгрывают ивент сразу. Ивенты — объекты контента, поэтому `events` без `items` не принимается (D-530); нужен раздел `events`. Выключен — `drawEvent` создаёт ручной эффект, как раньше (D-10), пакет с ивентами и колодами не принимается (D-532) |
| `weeklyChallenge` | челлендж недели (этап 5, D-526): админ задаёт челлендж с окном `weeklyChallenge.durationDays`, автоматический засчитывается расчётом после завершения, ручной отмечает админ; нужен `weeklyChallenge.durationDays`. Выключить нельзя, пока есть выполнение на прохождении с неодобренным пруфом (`ruleset.weeklyChallengeInPlay`, D-574) |
| `suggestions` | предложка (этап 5, D-527): игроки предлагают игры, ивенты и предметы, админ одобряет или отклоняет с комментарием; необязательное поле, нужен раздел `suggestions` |
| `polls`, `achievements`, `partnerBoard`, `reactions`, `comments`, `gallery` | соответствующие механики; пока их нет в сборке, включить их нельзя |
| — | выключенная механика не видна в интерфейсе, отклоняется движком (`feature.disabled`) и не пишет событий |
| `challenges` | заявка челленджа при завершении (D-96); необязательное поле, по умолчанию выключено, пока у игр нет заметки-челленджа и проверки пруфом |

### `season`

| Поле | Значение |
| --- | --- |
| `timezone` | часовой пояс для показа дедлайнов |
| `maxActiveRunsPerPlayer` | сколько прохождений одновременно у игрока |
| `maxUncheckedRuns` | сколько прохождений игрока может ждать проверки админом, прежде чем новый ролл закроется (D-134); `null` или нет поля — без лимита |
| `inactiveHintDays` | через сколько дней без действий игрок попадает в подсказку админу |

### `roll`

| Поле | Значение |
| --- | --- |
| `choiceCount` | сколько игр показывается на выбор при обычном ролле |
| `freeRerollsPerRoll` | бесплатные рероллы после каждого ролла |
| `rerollCost` | цена платного реролла: `{ "kind": "coins", "amount": N }` или `{ "kind": "badEvent" }` |
| `techRerollWindowHours` | окно тех-реролла после ролла |
| `minPlayMinutesBeforeDrop` | сколько нужно поиграть до дропа; на совести, используется в подсказках интерфейса |
| `emptyPoolFallback` | что делать, если под фильтрами нет игр: `dropZoneFilter` — снять фильтр зоны |
| `lastDaysLengthFilter` | ограничение длины игр в последние дни сезона, по шагам |
| `wishRerollTags` | теги, игры с которыми можно бесплатно отдать «по желанию» — тех-реролл с причиной `wish` в окне тех-реролла; не действует, если жанр навязан роллом (зоной, позже спецроллом или ивентом); сравнение без учёта регистра; фиксируется в снапшоте при ролле (D-206, D-325). Необязательное; по умолчанию `[]` — реролла по желанию нет |

### `reward`

| Поле | Значение |
| --- | --- |
| `diceCount` | число кубов: часы / `hoursPerDie`, округление `nearest`, `floor` или `ceil`, пределы `min` и `max` |
| `dieByDifficulty` | грани кубика по сложности; `grantEvent` — ивент в придачу |
| `challengeBonus` | награда за выполненный челлендж игры: `extraDice` — сколько кубиков того же типа добавляется после предела `max` (D-13); фиксируется в снапшоте при ролле |
| `unmetConditionPolicy` | невыполненное условие ивента: `noDiceKeepCoins`, `countAsDrop` или `ignore` |
| `coins` | монетки за прохождение: `max(min, ⌊min(часы, diceCount.max × hoursPerDie) × perHour⌋)`; фиксируется в снапшоте при ролле (D-96) |
| `coop` | доля очков в коопе и кому достаётся округление |

### `drop`

| Поле | Значение |
| --- | --- |
| `penaltyDice` | штрафной бросок |
| `affectsPoints`, `affectsPosition` | что отнимает штраф |
| `mandatoryEvent` | обязательный ивент при дропе: `bad` или `none` |
| `consecutiveExtraDice` | сколько кубиков штрафа (того же вида, что `penaltyDice`) добавляет каждый следующий дроп подряд: n-й дроп после последнего засчитанного прохождения бросает `count + (n − 1) × consecutiveExtraDice`; тех-реролл и отклонённое прохождение серию не меняют (D-205, D-324). Необязательное: `null` или нет поля — штраф не растёт; по умолчанию 1 |

### `finish`, `ranking`, `map`

| Поле | Значение |
| --- | --- |
| `finish.requireApprovalForFirst` | `true`: первый заморожен, когда одобрены пруфы всех его прохождений до финиша включительно; `false`: заморожен сразу при финише первым (D-99) |
| `finish.bonusByOrder` | бонус финишировавшим не первыми по порядку финиша |
| `finish.bonusAfterList` | бонус для всех, кто финишировал позже списка |
| `ranking.tiebreakers` | порядок тайбрейков: `completedRuns`, `earliestFinalScore` |
| `map.linearLength` | длина линейной карты в режиме `linear`; по умолчанию 70 — около 3,3 клетки на день сезона в 21 день (D-358, `docs/SIMULATION.md`) |
| `map.minZoneGames` | сколько доступных игр пула должен оставлять фильтр ролла зоны; меньше — предупреждение в редакторе, публикацию не блокирует (D-307); `null` или нет поля — без предупреждения |

### `economy`

| Поле | Значение |
| --- | --- |
| `allowNegativeCoins` | могут ли монетки уходить в минус от эффектов; при `false` эффект снимает не больше, чем есть; покупки и ставки в минусе запрещены всегда |
| `inventoryLimit` | сколько предметов держит инвентарь (эффекты и спецроллы не считаются, D-406): покупка сверх лимита отклоняется, подарок пропадает |
| `rarityWeights` | веса редкостей при выборе лотов магазина; редкость с весом 0 не выпадает |
| `shop.lotsPerRoll`, `shop.lotLifetimeMinutes` | сколько лотов даёт ролл магазина и через сколько минут они исчезают (время считает сервер) |
| `shop.rollCost`, `shop.rerollCostStep` | цена ролла магазина: `rollCost + rerollCostStep × роллов с последнего сброса`; бесплатный ролл (купон, ресурс `freeShopRolls`) тратится первым |
| `shop.resetOn` | когда цена ролла сбрасывается: `runCompleted`, `runDropped` |

### `effects`

| Поле | Значение |
| --- | --- |
| `maxChainDepth`, `maxEventsPerCommand` | лимиты цепочки эффектов на одну команду: от 1 и не больше защитных пределов SPEC — 3 уровня и 50 событий (D-418, D-489) |
| `hostileCap` | ограничение одновременных враждебных эффектов на игроке: при `enabled` враждебный предмет на цель, у которой `maxActive` враждебных объектов, отклоняется; выключено по умолчанию |
| `attacksOnlyOnHigherPoints` | враждебные эффекты достают только тех, у кого больше очков, чем у использующего |
| `reflect.coinsAtMost`, `reflect.multiplier` | отражение урона монетками (D-474): действие `changeResource` с `reflect: true`, снимающее монетки у цели, у которой их `coinsAtMost` или меньше (по умолчанию −30), снимает их у использующего, умноженные на `multiplier` (по умолчанию 2; не меньше 1). Нет поля — ничего не отражается (так играют сезоны, созданные до правила) |

### `interactions`, `bets`

| Поле | Значение |
| --- | --- |
| `interactions.inviteTtlHours` | через сколько сгорает приглашение в кооп или на дуэль |
| `bets.maxStake`, `bets.maxOpenBetsPerPlayer` | лимиты ставок |
| `bets.windowHoursAfterRoll` | сколько часов после ролла можно ставить на это прохождение |
| `bets.deadlineOptionsDays` | варианты срока ставки |
| `bets.payoutByHoursPerDay` | коэффициент по нагрузке: часы игры из снапшота / дни до срока, первый шаг с часами в день ≤ `upTo`; `upTo: null` — без верхней границы; игра без часов — первый шаг; выигрыш — ⌊ставка × коэффициент⌋ (D-414) |

### `social`, `nominations`, `weeklyChallenge`

| Поле | Значение |
| --- | --- |
| `social.reactions` | набор эмодзи для реакций |
| `social.galleryUploadsPerDay`, `social.commentsPerDay` | лимиты на человека в день |
| `social.spectatorsCanVote` | голосуют ли зрители |
| `nominations.auto` | автоматические номинации |
| `nominations.voted` | номинации голосованием |
| `weeklyChallenge.defaultRewardCoins` | награда за челлендж недели по умолчанию |
| `weeklyChallenge.durationDays` | сколько дней длится окно челленджа от его начала, 1–366; считается время завершения прохождения, окно `[начало, начало + дни)` (D-526, D-574). Необязательное поле (конфиг, записанный до него, читается), обязательно при включённом `features.weeklyChallenge`. По умолчанию 7 |

### `suggestions`

Необязательный раздел (этап 5): конфиг сезона, записанный до него, читается без раздела; при включённом `features.suggestions` раздел обязателен.

| Поле | Значение |
| --- | --- |
| `suggestions.perDay` | сколько предложений один игрок подаёт за календарный день по `season.timezone`, 1–100; отклонённые тоже считаются (D-527, D-571). По умолчанию 5 |

### `events`

Необязательный раздел (этап 5): конфиг сезона, записанный до него, читается без раздела; при включённом `features.events` раздел обязателен.

| Поле | Значение |
| --- | --- |
| `events.defaultDeck` | `good`, `bad`, `special`, `risky` — стандартная колода, из которой тянет клетка ивента `deck: zone`, когда у зоны клетки нет колоды или клетка вне зоны (D-502). По умолчанию `risky` |
| `events.answerTimeoutHours` | Срок ответа ивента в часах (D-560): сколько ивент с вопросом ждёт ответа игрока, потом таймер отвечает за него случайным вариантом, ответ записан в лог. Не меньше 1 и не больше 8760; `null` или поле отсутствует — ждёт без срока (ход стоит, админ может снять ожидание). По умолчанию `null` |
| `events.irlProof.maxFiles` | Сколько своих загруженных картинок принимает одна подача IRL-пруфа (D-509, D-680): от 0 до 5 (предел скринов пруфа прохождения); 0 — только ссылка. Ссылка на видео одна, только `https`, без логина и пароля в адресе, не длиннее 500 символов (как у пруфа прохождения); сервер её не открывает. Блок `events.irlProof` обязателен при включённых `features.events`; в сезоне, правила которого записаны до него, отсутствует. По умолчанию 5 |
