# Стратегия тестирования

Цель: каждое правило покрыто автоматическим тестом, а агент сам ищет баги как живой пользователь и закрывает каждый найденный баг регрессионным тестом.

## Слои тестов

| Слой | Инструмент | Что проверяет | Когда запускается |
| --- | --- | --- | --- |
| Архитектурные тесты и анализаторы | NetArchTest, BannedApiAnalyzers | движок не зависит от веба, БД и системного времени; запрещённые API не используются | каждый коммит |
| Сценарные тесты движка | xUnit | каждое правило спецификации: дано состояние → команды → события и состояние | каждый коммит |
| Инварианты на случайных партиях | FsCheck + xUnit | тысячи случайных последовательностей команд; после каждой проверяются инварианты | короткий прогон на каждый коммит, длинный ночью в CI |
| Симулятор баланса | xUnit | боты играют через движок: детерминизм по зерну, отказы движка не зацикливают ботов, агрегаты отчёта на ручном примере, карта-граф | каждый коммит |
| Интеграционные тесты API | xUnit + WebApplicationFactory, временная SQLite | права доступа, валидация, файлы, очередь команд под параллельной нагрузкой, SignalR | каждый коммит |
| Компоненты фронтенда | Vitest + Testing Library | логика и состояния компонентов | каждый коммит |
| E2E | Playwright | сквозные сценарии несколькими пользователями, экран телефона | каждый push в CI |
| Конфиг и контент | xUnit | `ruleset.default.json` проходит схему; каждый пример из `CONTENT.md` загружается и работает как описано | каждый коммит |
| Миграции | xUnit + копия демо-базы прошлой версии | миграции применяются к реальным данным без потерь | каждый коммит с миграциями и перед деплоем |
| Контракт API | CI | сгенерированный TypeScript-клиент совпадает с OpenAPI | каждый push |
| Проверка восстановления | `npm run backup:verify` | последний бэкап разворачивается и проходит проверку целостности | раз в неделю на сервере |
| Мутационное тестирование | Stryker.NET по движку | ловят ли тесты подмену логики | в конце каждого этапа |
| Исследовательское тестирование | агент в браузере | поведение как у живых людей, попытки сломать | в конце каждого этапа и по запросу |

## Требования к покрытию

- **Движок**: не меньше 90% веток по coverlet. Мутационный счёт Stryker по движку не ниже 80%.
- **Матрица правил**: `docs/TEST_MATRIX.md` связывает каждое правило из `docs/SPEC.md` и каждую строку «Проверки на дыры» с тестами. Правило без теста — незакрытая задача.
- **Каждый эндпоинт API**: тест на успех, тест на запрет чужой роли или чужому игроку, тест на невалидный ввод.
- **Каждый найденный баг**: сначала падающий тест, потом исправление.
- **Тест нельзя удалить, пропустить или ослабить, чтобы он прошёл.** Если тест неверен, причина записывается в `docs/DECISIONS.md` и согласуется.

## Инварианты для случайных партий

Генератор играет сезоны случайными допустимыми командами игроков и админа (включая откаты, реджекты и перемотку времени) и после каждой команды проверяет:

1. Состояние, пересчитанное из лога, совпадает с сохранённым.
2. Очки и монетки игрока равны сумме изменений в неотменённых событиях.
3. У игрока не больше разрешённого числа активных прохождений.
4. Одну игру одновременно играет не больше одного прохождения; кооп — одно прохождение.
5. Игра, пройденная в сезоне, больше никому не выпадает.
6. Своя дропнутая или техдропнутая игра игроку не выпадает.
7. Позиция всегда на существующей клетке, не позади старта и последнего пройденного чекпоинта после штрафов.
8. После финиша первым очки и позиция игрока не меняются, эффекты от других к нему не применяются.
9. Бонус финиша каждому выдан не больше одного раза, позиция финишировавшего не меняется.
10. Порядок лидерборда соответствует правилам мест и тайбрейков.
11. После дедлайна нет бросков.
12. Цепочка эффектов не превышает лимитов.
13. Откат команды без зависимых команд возвращает ровно то состояние, что было до неё.
14. Одинаковое зерно случайности и одинаковые команды дают одинаковый лог.
15. В минусе по монеткам нет покупок.
16. Эффекты от других не меняют уже начатый шаг.
17. Сумма залогов равна сумме открытых ставок, ставок на себя нет, реджект отменяет выигрыш.
18. В голосовании не больше одного голоса от пользователя.
19. Выключенная флагом механика не порождает событий.
20. Достижение выдаётся не больше одного раза в своей области: сезон или всё время.

Как это устроено на этапе 1 (C13, D-111):

- **Короткий прогон** — свойства FsCheck (`[Property(MaxTest = …)]`, обычно 200 партий) в `npm run test:fast`. Самое широкое — общая партия `Invariants/PlayerAdminInvariantTests.Invariants_hold_in_the_combined_game`: игроки, админ, часы, дедлайны, пруфы, откаты и правки правил вместе.
- **Длинный прогон** — `npm run test:invariants:long [-- <партий>]` (ночью в CI): каждое свойство ещё раз на `INVARIANT_RUNS` партиях (по умолчанию 20 000), сценарии до `INVARIANT_SIZE` команд (150). Около 2,5 мин на 16 ядрах.
- **Падающая партия** печатается в сообщении как код билдера `Scenario` (уже сжатая FsCheck): `var s = Scenario.New(seed: …); s.WithGame(…); s.Act(new RollGame(s.PlayerId("Вася"))); …` — его можно вставить в сценарный тест и так воспроизвести баг.
- С откатами эталонные свёртки читают `Scenario.EffectiveLog` — лог без отменённых команд и самих откатов.

## Тестируемость

- **Окружение Test** с эндпоинтами «перемотать время», «загрузить сценарий», «зафиксировать зерно случайности». Они регистрируются только в Development и Test; в Production их нет физически, и это проверяет отдельный тест.
- **`data-testid`** на всех интерактивных элементах.
- **Анимации** колеса и кубиков отключаются флагом в тестах.
- **Изоляция**: каждый E2E-тест создаёт свой сезон и своих игроков, тесты не зависят друг от друга и от порядка запуска.
- **Билдер сценариев** для тестов движка: `Scenario.WithPlayers(3).Roll("Вася").Complete(hours: 6)…`. Тест должен читаться как описание партии.
- **Снапшот-тесты лога** (библиотека Verify): ключевые сценарии сохраняют итоговый лог событий в файл, изменение поведения видно как разница в файле. Этап 1: `src/GameEvent.Engine.Tests/Snapshots/LogSnapshotTests.*` — лог в хранимом виде (тип, версия, JSON) по командам в `*.verified.txt`. Изменение, которое так и задумано, принимается переименованием `*.received.txt` в `*.verified.txt` после просмотра разницы (D-112).
- **Сценарии для ручной проверки**: те же сценарии загружаются кнопкой в тестовой копии и в разработке («финиш на носу», «дедлайн через час», «на игроке пять эффектов»).

## E2E-сценарии, минимум

1. Полный цикл: админ создаёт сезон и трёх игроков → вход → ролл → прохождение с пруфом → кубы → движение → другой игрок видит обновление без перезагрузки → админ одобряет.
2. Дроп: штраф по очкам и позиции, ручной плохой ивент появляется в списке.
3. Тех-реролл в окне и после окна (перемотка на 49 часов).
4. Реджект: очки и клетки снимаются.
5. Финиш: первый финиш предварительный, одобрение и заморозка; второй финиш с бонусом; реджект первого финиша и пересчёт мест.
6. Дедлайн: броски запрещены, пруфы принимаются, итоги после проверки.
7. Откат действия админом.
8. Права: игрок не открывает админку и не действует за другого.
9. Экран телефона 390×844: главная, прохождение, карта с зумом.
10. Две вкладки одного игрока и параллельные клики.
11. Зритель видит всё публичное и не может сделать ни одного игрового действия.
12. Страница правил показывает числа из текущего конфига, после правки конфига админом — новые числа и запись в истории.
13. Скорость главной на демо-сезоне с эмуляцией мобильной сети укладывается в бюджет из `docs/DESIGN.md`.

Сценарии механик следующих этапов (карта, магазин, ставки, голосования, реакции и остальное) добавляются вместе с этими этапами.

## Исследовательское тестирование агентом

Проводится субагентом `bug-hunter` через навык `/bughunt`.

1. Поднять сайт с демо-сезоном: `npm run dev:demo`.
2. Пройти сайт в браузере через Playwright: через Playwright MCP, если он подключён, иначе скриптами Playwright со скриншотами, которые агент сам просматривает.
3. Играть за персонажей:
    - **новичок**: заходит впервые, путается, жмёт не туда, ищет, что делать дальше;
    - **хитрый игрок**: обновляет страницу во время колеса, жмёт кнопки дважды, открывает две вкладки, подделывает запросы (чужой id, сложность, часы), грузит не те файлы и огромную гифку, даёт ссылку на внутренний адрес вместо аватарки, действует после дедлайна;
    - **админ**: массовые правки, откаты и реджекты в неудобный момент;
    - **игрок с телефона**: узкий экран, медленная сеть.
4. Отдельно проверить: пустые состояния (нет игр, нет игроков), очень длинные названия, эмодзи и кириллицу в именах, перезапуск сервера посреди таймера.
5. Каждая находка → запись в `docs/BUGS.md` (номер, шаги, ожидалось, получилось, важность, скриншот) → падающий тест → исправление → отметка «исправлено».
6. Итог сессии в `docs/PROGRESS.md`: найдено, исправлено, осталось и почему.

## Визуальные регрессионные тесты

- `e2e/visual` (конфиг `e2e/playwright.visual.config.ts`): карта и разделы `/styleguide` в Chromium, Firefox и WebKit, на телефоне 390×844 и десктопе 1440×900. Скриншоты сравниваются с эталонами `e2e/visual/__screenshots__/<движок-размер>/`.
- Карта дополнительно проверяется по пикселям: середина дороги светлая, зона не заливается чёрным (баг D-132). Эта проверка не зависит от эталонов.
- Скриншоты разные на разных системах, поэтому тесты идут только в контейнере Playwright той же версии, что `@playwright/test` в `e2e`: `npm run test:visual` (собирает фронтенд и запускает Docker), в CI — задача `visual`.
- Изменился дизайн намеренно — пересними эталоны: `npm run test:visual -- --update-snapshots`, просмотри новые картинки и закоммить их вместе с изменением.

## CI

Полная схема — раздел «CI/CD» в `docs/SPEC.md`.

- **На каждый push**: сборка, анализаторы, архитектурные тесты, быстрые тесты, короткий прогон инвариантов, проверка клиента API, gitleaks.
- **Перед слиянием в `main`**: плюс E2E на демо-сезоне и проверка миграций на копии базы прошлого релиза (`npm run test:migrations`, задача CI `migrations` на PR с изменениями бэкенда, J5).
- **После выкладки на тестовую копию и на боевой сайт**: дымовые тесты `@smoke`; на боевом только чтение.
- **Ночью, если были коммиты**: длинный прогон инвариантов. Раз в неделю — Stryker.
- **Артефакты**: отчёт о покрытии, трассы Playwright и скриншоты упавших тестов.
- **Бюджет минут**: кэш зависимостей, отмена параллельных прогонов, фильтры путей. Если репозиторий приватный на бесплатном тарифе, следи, чтобы месяц укладывался в лимит минут.
- Выкладка на боевой сайт возможна только для версии, прошедшей все проверки и тестовую копию.
